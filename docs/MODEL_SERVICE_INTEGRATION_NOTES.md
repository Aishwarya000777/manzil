# Model integration notes — conditional-routing branch

## Branch to use

Apply this overlay to `feature/conditional-llm-routing` (not the older `feature/destination-understanding`). The former contains the full application and the protected conditional-routing files documented by the partner's `readme1.md`.

## Files intentionally not modified

The overlay contains no `backend/` directory. It does not change:

- `backend/ambiguity.py`
- `backend/conditional_router.py`
- `backend/ml_response_formatter.py`
- `backend/main.py`
- `backend/response_normalizer.py`
- `backend/model_service.py` (coordinate with the partner before any future edits)
- any frontend, speech/Whisper, Gemini/LLM or route implementation.

## What gets replaced/added

1. Replace only `models/manzil_linear_crf.pt` with the new checkpoint.
2. Preserve the original CRF checkpoint as `models/manzil_linear_crf_baseline_backup.pt`.
3. Keep `models/intent_char_tfidf_logreg.joblib` unchanged. The copy in the patch is byte-identical to the current package version; the apply script does not overwrite it.
4. Add the clean/augmented JSONL datasets, data audit, training script, evaluation artifacts, annotation workbook, Colab notebook and documentation. These are training/research assets, not runtime requirements for the app once the model file is present.

## Compatibility checks

The improved CRF checkpoint matches the existing `backend.model_service.LinearChainCRF` contract:

- `feature_dim=4096`;
- 15 tags with exactly the same order as the original checkpoint;
- state-dict keys `em`, `trans`, `start`, `end`;
- tensor shapes `(4096,15)`, `(15,15)`, `(15,)`, `(15,)`;
- identical token-feature templates (lowercased word, word shape, length, prefixes/suffixes, BOS/EOS, previous/next token and bigrams).

The existing backend Viterbi decoder adds `self.start` and `self.trans` directly. The new checkpoint stores large negative scores for illegal `I-` starts and illegal BIO transitions. Thus the existing decoder enforces BIO legality without backend edits.

`model_service.predict(query)` retains the same prediction output fields. `intent_confidence`, `intent_probabilities` and `intent_margin` remain generated by the existing intent classifier code, and the intent classifier checkpoint is unchanged.

## Validation after applying

From the repository root on `feature/ner-crf-improvement`:

```bash
python scripts/audit_ner_dataset.py --data data/manzil_v2_token_level_clean_augmented.jsonl
python scripts/smoke_test_model_service.py
```

The smoke test loads the new checkpoint through the real partner backend and checks the seven spans in the Madhapur/ATM regression example. Then start the full backend and frontend and test both ML_ONLY and ML_WITH_LLM paths. This environment did not have a full local clone of the partner app, so full FastAPI/frontend integration is still pending.

## Routing-threshold note

The current architecture README/code specify `intent_confidence < 0.50` and `intent_margin < 0.20`. The partner's voice explanation mentioned a confidence threshold of `0.75`. This patch deliberately leaves the current router and thresholds untouched; confirm the intended value with the partner before changing routing.
